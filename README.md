# Digital Rain

Matrix-inspired rain app, currently **Signal Engine 16**. Open `index.html` in a modern browser or serve the directory with any static web server. No build step, backend, or saved settings.

## Current state

**Experimental Code Tunnel:** choose Code Tunnel under Reality in the panel, or press **V** to switch between rain and tunnel. Fly through a bending, banking, corkscrewing tube of animated Matrix glyph trails, with bright heads, depth fog and phosphor halos. Turn on music with the music-note button: Beat Impact controls acceleration, wall pressure waves and lighting. All four profiles, CRT modes, density, zoom, speed, persistence and glow remain available. CRT curvature is bypassed in the tunnel while scanlines remain active; returning to rain restores the selected curvature. Click sends ripples across the walls; E launches a wave down the tunnel; B tears it apart. Pause freezes flight and code, and switching modes retains the flight position. Reseed generates a new wall pattern; Restore Defaults returns to rain. Touch devices use fewer circumferential lanes.

Three visual depths of stationary, mutating glyph cells create falling streams, with phosphor bloom, grain, and bright green heads in Source. Four profiles (**Source, Deep, Overdrive, Anomaly**) theme both rain and controls. Source keeps the classic cadence; Deep drifts slowly with quieter glyph mutation; Overdrive falls faster with restless glyphs; Anomaly surges unevenly with faster mutation and more broken trails. Selecting a different profile loads its density, trail persistence, speed, mutation and glow presets, with the available sliders showing those values directly. Deep uses sparse, longer trails; Overdrive uses dense, shorter trails; Anomaly uses dense, fragmented trails. These values remain editable; camera zoom retains your setting. Profile changes preserve existing streams. Display modes are flat, scanlines, and curved CRT. Curved CRT fills the viewport through slight overscan/cropping, with pointer mapping following the same transform.

Interactions include ripples, electric surge, system breach, and fullscreen. System breach opens with a blackout and flash, then tears the code into displaced slabs around a dark central fissure before the sections relock independently over 3.2 seconds. Its sound follows the tear with outward-moving metallic strain, low pressure tones, and staggered mechanical latches timed to the sections returning. Wheel/pinch zooms (65–200%); mobile horizontal dragging pans.

Audio is synthesized with Web Audio: SFX Only, Static Hum, or four distinct original profile scores with beat-reactive lighting. Deep plays orchestral trip-hop, Overdrive industrial metal / EBM, Anomaly dub / jungle, and Source plays the approved original 134-BPM breakbeat score. See [MUSIC.md](MUSIC.md) for research and audition notes. Defaults: Source, curved CRT at 100% curvature with scanlines at 85% contrast, film grain at 35% (0% disables it), UI sound level at 40%, static hum volume at 50%, SFX Only armed until the first user gesture. Curved CRT has an adjustable 0–200% curvature control; 100% preserves the original curve. The music-note button toggles Score + Hum / SFX Only and starts off. The settings icon opens the system panel. Static hum and score have independent volume sliders, with beat controls below all audio levels; clicking or tapping the canvas closes it. Pause freezes rain and score and ignores rain hover/click/tap disturbances. Camera and appearance controls still work; hum and UI sounds can continue. Muted silences everything.

Audio uses the browser's default `AudioContext` construction and native sample rate on all devices. Scores share a 170 ms look-ahead, 12 ms minimum voice lead and 75 ms start lead. After stalls, missed ticks are skipped on the existing tempo grid instead of starting together. Completed sounds disconnect their full voice graph, instrument presets are reused, UI starts use the clock after sample generation, and ambient mode changes fade briefly to avoid hard cuts.

Beat visuals follow the audio output-device timestamp where supported, falling back to reported output/processing latency. A brief 35 ms attack hold keeps hits visible at 30 FPS, followed by a faster release. Tunnel impact preserves that contrast instead of lifting the whole decay. Tunnel rendering caches bounded wall seeds and per-cell glyph lookups, shares lane/section calculations, and uses one transform per glyph. Rain simulation rests while the tunnel is active and resumes its retained streams when switching back. See [PERFORMANCE.md](PERFORMANCE.md) for measurements and verification limits.

The speculative touch latency/timing branches and Android hardware render-size hint were removed after they showed no demonstrated benefit for the reported Firefox fault. Synthesized attacks again start at the established `0.0001` gain floor; short final fades to zero remain. UI Foley components and processed buffer edges retain their tapers, addressing measured nonzero cuts such as the earlier panel-close ending at about 0.062 amplitude at 48 kHz. Compositions and volume calibration are retained. Browser rendering and mock checks cannot prove dropout-free device playback. See [AUDIO_HANDOFF.md](AUDIO_HANDOFF.md) for the applied cleanup and preserved investigation history.

**Controls:** Space pause/resume; M music on/off; Shift + M mute/restore all audio; S settings; Esc close settings; F fullscreen; V rain/tunnel; C cycle signal profile; 1 flat, 2 scanlines, 3 curved CRT; T film texture; G phosphor glow; E electric surge; B system breach; R reseed; +/− column density. Click/tap the running rain for ripples; Shift + click strengthens the wave. Wheel/pinch zooms; horizontal touch dragging pans. Clicking or tapping the signal status or its dot pauses/resumes the signal. Controls help at the top of settings groups desktop shortcuts and shows touch gestures on phones. Hover hints, button keycaps and accessibility shortcuts share one registry. Space pauses from any control; Enter activates a focused button or checkbox.

## Decisions from the Git history

- **Keep streams collision-free** (`a3129c4`, `9461c35`): each global horizontal lane belongs to one depth. Each stream now samples its own steady base speed within its depth range; Fall Velocity scales that range. Births wait for trajectory clearance against every stream ahead, retaining at least two dark rows without slowing followers. After viewport growth, existing trails extend only when clearance permits; otherwise they finish at their original bottom boundary while new births cover the expanded field. Density changes lane activation and future gaps. Effects modify existing cells; draw bloom before glyphs.
- **Preserve the world during zoom** (`4f401b1`, `d5e207b`, `a8ab1f0`): `zoom` controls the camera, not glyph size. Zoom, pan, and resize preserve existing streams; larger viewports add coverage around the fixed world centre. Reseed and Restore Defaults rebuild the world. Ripples propagate in viewport pixels, and pointer input follows CRT sampling transforms. Keep these coordinate systems consistent.
- **Maintain mobile resilience** (`dbded01`, `a8ab1f0`): all devices use the native Canvas 2D runtime. Coarse primary pointers target 30 FPS; fine primary pointers, including touchscreen desktops, target 60 FPS. CRT uses WebGL where available on desktop and retains its Canvas fallback; coarse-input devices use Canvas CRT processing. Touch support is a fallback when no fine pointer is reported. Pixel density 1, cached atlases/halos, and tiled grain control cost. Optional Google Fonts arrival rebuilds atlases without reseeding.
- **Preserve CRT exposure and readable themes** (`d5e207b`, `ee44cba`): distortion processes the final raster; scanline darkness has brightness compensation. Panels stay subtly translucent with near-white text and backdrop blur to soften glow behind the controls. Profile keys remain `cinema`, `abyss`, `voltage`, `anomaly` despite renamed labels.
- **Keep input/audio ownership clear** (`dbc7bb7`, `afa8d4d`, `a8ab1f0`): one capture-phase shortcut dispatcher handles focused controls without double actions; native pointers distinguish taps from gestures. Shift + M restores the previous audible mode. Separate score/UI/cinematic audio routing supports pause behavior.
- **Retain mechanical UI Foley** (`2103b5b`, `e7f88f1`, `a8ab1f0`): worn hardware sounds replaced electronic beeps. Preserve ON/OFF switch timbres, weighted buttons with subtle pitch variation, and soft/throttled slider detents. UI level 50% matches the earlier 25% calibration without altering score/cinematic levels. No imported movie audio.

## Guidance for future changes

The app uses six files: `index.html` for structure, `styles.css` for presentation, `js/rain.js` for the Canvas runtime and simulation (`CodePlane`, `CodeLane`, `CodeStream`), `js/crt.js` for `CRTDisplay`, `js/audio.js` for `SignalAudio`, and `js/ui.js` for controls and keyboard dispatch.

Classic scripts load in that order. UI installs the Canvas runtime after the app dependencies are defined; the scene starts once at `DOMContentLoaded`. Open `index.html` directly or serve this directory; no module loader or build is required. Rendering requires no external library or network access. Google Fonts are optional, with system fonts available offline. Display/audio read the small `RainApp` interface, while controls use `setRainOption`, `getRainOptions`, action functions, and `rain-state` to synchronize state.

`RainApp.settings` defines defaults, numeric limits, accepted choices, and display formatting. The public setter rejects invalid values and clamps finite numbers. Updates advance streams, mutation, and effect bookkeeping separately from rendering; appearance changes can redraw a paused scene without advancing its clock. Native pointers share CRT coordinate correction for hover and taps.

Reduced-motion preference starts the app paused. Pause/Resume, Space, or a manual surge/breach establishes your animation choice, which later preference changes preserve. Restore Defaults follows the current preference again. Interface transitions also respect reduced motion.

Run `node tests/checks.js` for dependency-free regression groups using mocked DOM, Canvas, and Web Audio. These execute the app's Canvas startup, settings/reset/mute/shortcut behavior, frozen rendering, lane scheduling, overlapping ripple ownership, viewport culling, coordinate mapping, gestures, scheduled audio routing, and motion-preference logic. Audio checks also cover common scheduling defaults, recovery from short/long stalls, complete voice cleanup, shared effect lifetime, and uncached UI sample timing. Startup checks reject external script injection and verify a single scene on desktop and mobile. Mocks do not establish browser appearance, audible output, GPU performance, or real-device behavior. Current component browser checks and outstanding acceptance checks are recorded in `TODO.md`.

An optional Playwright check measures real-browser frame work: `node tests/perf.js --output after.json`; add `--ref <commit>` to measure a prior revision. `--native-input` measures the production animation clock with the browser's actual pointer reports and real audio beat envelopes, covering touchscreen desktop classification. `--verify-ref <commit>` compares tunnel pixels at matching beat inputs and checks real Web Audio beat envelopes; `--screenshots <directory>` saves browser captures for the controlled graphics cases. Requires Playwright resolvable by Node (or `NODE_PATH`) and installed Microsoft Edge; set `PERF_BROWSER=chrome` for installed Chrome. The app itself remains dependency-free.

Analog Display includes **SHOW FPS**, off by default. It shows the measured scene rendering cadence in the top-right corner, averages about one second of frames, displays zero on pause and turns off when defaults are restored. On mobile, **UNLOCK 60 FPS** appears directly below it and raises the default 30 FPS limit to 60 FPS. Turning it off or restoring defaults returns to 30 FPS; desktop remains at 60 FPS.

`tests/profile.js` adds alternating before/after runs, component costs, bounded-memory soak checks, WebGL GPU timer queries, and audio scheduling diagnostics. `tests/visual-perf.js` compares rain, tunnel, grain, effects, CRT output, pause, resize and pointer mapping against a Git revision; it also requires `pngjs`. See [PERFORMANCE.md](PERFORMANCE.md) for the current results, rejected experiments, commands and measurement limits.

After relevant changes, check desktop and mobile Canvas rendering, both CRT processing paths, maximum density, zoomed CRT edge clicks, tap/pinch/pan/cancellation, focused shortcuts, mute restoration, pause, and resize. See `RUNTIME_EVALUATION.md` for the Canvas runtime decision and remaining verification limits.
